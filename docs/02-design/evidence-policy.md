# 근거 표기 규약 — 검증된 것과 제안을 섞지 않는다

이 리포의 문서는 주장마다 **어디서 온 것인지**를 표시합니다. 이유는 하나입니다 —
**문서로 검증된 것, 코드로 확인한 것, 아직 제안인 것을 섞어 말하면 전부 못 믿게 되기
때문입니다.**

## 표기 3종

| 표기 | 뜻 | 확인 방법 |
|---|---|---|
| `[문서]` | 제품 공식 문서·표준 문서로 확인 | URL 또는 문서 경로를 함께 남김 |
| `[코드]` | 이 리포의 코드·설정을 직접 읽거나 실행해 확인 | 파일:라인, 또는 실행 출력 |
| `[제안]` | 아직 구현하지 않은 아이디어 | 근거가 있어도 "될 것"이지 "된다"가 아님 |

세 상태로 정리합니다 — **검증됨** / **확인됨** / **미확인** / **근거 미발견**.

- **미확인**과 **근거 미발견**을 구분합니다. 앞엣것은 "우리가 안 찾아봤다", 뒤엣것은
  "찾아봤는데 못 찾았다"입니다. 뒤엣것을 "없다"로 단정하지 않습니다.

## 왜 이렇게까지 하나

이 PoC에서 **가정이 조사로 뒤집힌 사례가 실제로 여러 번** 있었습니다.

- "실환경 DNS는 질의 내용을 아무도 못 본다" → **틀렸습니다.** dnsdist가 네이티브로 다섯 경로를
  제공합니다. 조사 없이 발표했으면 그 자리에서 논거가 무너졌을 것입니다
  ([ADR-004](decisions/adr-004-suricata-defer.md)).
- "Wazuh FIM을 켜면 레벨 11이라 Slack이 터진다" → **틀렸습니다.** 공식 분류표의 "11 = integrity
  checking warning"은 레벨의 **의미 설명**이지 FIM 룰의 실제 레벨이 아닙니다. 실제 FIM 룰은
  5~7이고, 문제는 폭증이 아니라 **소실**이었습니다
  ([severity-normalization §3-1](severity-normalization.md)).
- "HolmesGPT는 쿠버네티스 지향이라 우리 스택에 안 맞는다" → **틀렸습니다.** 공식 문서에
  "any infrastructure: VMs, bare metal, cloud"라고 있습니다
  ([ADR-002](decisions/adr-002-holmesgpt.md)).

셋 다 **그럴듯했고, 셋 다 공식 문서 한 번으로 깨졌습니다.** 그래서 규약을 둡니다.

## 수치에 적용할 때

1. **비율과 절대값을 구분합니다.** 이 리포의 공개 문서는 **비율·구조만** 씁니다
   (호스트 대수·총 이벤트 건수 같은 모수는 조직 식별 가능성 때문에 쓰지 않습니다).
2. **측정 창을 병기합니다.** 같은 도구라도 실행 날짜가 다르면 30일 창이 달라집니다.
   **서로 다른 창의 수치를 한 문장에 섞지 않습니다.**
3. **의미가 다른 용어를 섞지 않습니다.** "이벤트 발생 수(트리거 발화)"와 "알림 발송 수"는
   다른 값입니다. 액션 조건을 통과한 것만 발송되기 때문입니다.
4. **수치는 원본에서 재계산 가능해야 합니다.** 측정 도구의 원시 출력을 함께 보관합니다.
5. **랩 값과 실환경 값을 섞지 않습니다.** 이 리포의 측정값은 대부분 랩 값이고, 그렇게 밝힙니다.

## 문서에 적용할 때

- **완료를 과장하지 않습니다.** 상태는 세 값만 씁니다 — **랩 실증** / **코드 있음·미실증** /
  **미구현**. "완료"라는 말은 쓰지 않습니다.
- **변하는 숫자를 박제하지 않습니다.** 셀프테스트 통과 건수처럼 커밋마다 바뀌는 값은
  작성 시점에 재산출하거나 "실행해서 확인"으로 적습니다.
- **못 한 것과 안 한 것을 구분합니다.** 설계로 안 한 것을 한계로 적으면 실제보다 못해 보이고,
  못 한 것을 설계라고 적으면 거짓말이 됩니다
  ([limits.md §4](../03-pitfalls/limits.md) 참조).

## 검증 상태 표를 쓰는 방법

긴 문서에는 끝에 검증 상태 표를 둡니다. 예:

| 주장 | 출처 | 상태 |
|---|---|---|
| Zabbix `forecast()`·`timeleft()` 예측 함수 존재 | 문서 | 검증됨 |
| 현행 봇에 예측 없음 | 코드 | 확인됨 |
| Grafana ML forecasting = Cloud 전용 | 문서 | 검증됨 |
| Keep이 "90일 빈도 만성 랭킹"을 네이티브로 제공하지 않음 | 문서 | **근거 미발견**(단정 아님) |
| `countOutput`으로 정확한 개수 취득 가능 여부 | 문서 | **미확인** |
| 만성 자동화 후보 랭킹 | 제안 | **미구현** |

**"검증됨"만 사실로 진술하고, "제안"은 로드맵으로 정직하게 구분합니다.**
