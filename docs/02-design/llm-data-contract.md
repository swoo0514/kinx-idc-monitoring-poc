# LLM 전송 데이터 계약 — 무엇을 보내고, 무엇을 안 보내는가

외부 LLM으로 나가는 데이터의 명세입니다. **이 문서가 원본이고 코드가 추종합니다**
(`bot/gateway/masking.py`, `bot/gateway/collector.py`). 셀프테스트가 문서-코드 일치를
검증합니다.

## 1. 통제 원칙 3줄

1. **단일 반출구** — 외부 LLM 통신은 게이트웨이 한 곳에서만 발생합니다. 에이전트·Zabbix·
   Wazuh는 외부와 직접 통신하지 않습니다.
2. **화이트리스트** — 허용 필드만 직렬화합니다(`build_llm_context`가 화이트리스트 그 자체).
   목록에 없는 필드는 **구조적으로 전송 불가**이므로 "빼먹고 보냄"이 코드상 일어날 수 없습니다.
3. **가명화 왕복** — 식별자(호스트명·IP·그룹명)는 `[host-1]` 형태 토큰으로 치환해 보내고,
   회신의 토큰을 게이트웨이가 역치환해 Slack에는 실명으로 게시합니다. **가명 맵은 게이트웨이
   메모리에만 존재합니다.**

## 2. 전송 항목 (화이트리스트 전체)

| 항목 | 예시 | 처리 |
|---|---|---|
| 알림명 | `Filesystem /data 사용률 92% on [host-1]` | 호스트명 부분 가명화 |
| 통합 심각도 | `SEV2` | 원값 (자체 눈금) |
| 발생 시각 | unix time | 원값 |
| 호스트 | `[host-1]` | **가명** |
| 호스트그룹 | `[group-1]` | **가명** (MSP 고객사명이 들어갈 수 있으므로) |
| 트리거 설명·조건식 | `last(/[host-1]/vfs.fs.size[...])>90` | 조건식 안의 호스트명도 가명화 |
| 메트릭 키·단위·최근 추이 | `vfs.fs.size[/data,pused]`, `%`, 수치 배열 | 원값 (수치·키는 비식별) |
| **로그 라인 (Loki)** | `... [host-1] backup: mysqldump from [ip-2]` | 라인 내 호스트명·IP 가명화 + **라인당 300자·최대 40줄** 제한 |
| **보안 경보 (Wazuh)** | `{level:10, desc:"brute force on [host-1]"}` | desc 내 식별자 가명화, **최대 20건** |
| **보안 경보 — 룰 식별** | `{rule_id:"550", groups:"syscheck,pci_dss_11.5"}` | 원값 — **식별자 없음**(룰 번호·그룹명은 Wazuh 공용 값). 봇이 "무슨 종류의 보안 이벤트인지"를 알아야 노이즈성 변경과 유의미한 변경을 구분합니다 |
| **파일 변경 경로 (FIM)** | `syscheck.path` → `/etc/ssh/sshd_config`, `syscheck.event` → `modified` | **경로 문자열도 가명화를 거칩니다** — 경로에 호스트명·IP가 섞일 수 있어 경로 자체가 새 누수면입니다 |
| 선판정 결과 | `신규 — 최근 90일 내 발생 이력 없음...` | 원값 (코드가 만든 문장) |
| **교차 소스 조회 상태** | `{"logs":"ok","security":"unavailable"}` | 원값 — 상태 문자열 3종(`ok`/`unavailable`/`disabled`)만 통과하고 그 밖은 `unknown`으로 강등 |

마지막 항목이 중요합니다. **"조회 실패"와 "신호 없음"을 구분하지 않으면**, Wazuh 인덱서가
죽었을 때 봇이 "침해 흔적 없음"을 단언하게 됩니다. 그 구분을 계약 수준에서 강제합니다.

## 3. 비전송 항목 (명시적 차단)

- 크리덴셜 전 종류 — Zabbix 토큰, 게이트웨이 토큰, SNMP community, 비밀번호
- 호스트명·IP(공인/사설 불문)·고객사명의 **원문** — 가명 토큰만 나갑니다
- 사용자 계정명, 이메일, Slack 채널명
- Zabbix 이벤트/트리거의 화이트리스트 밖 메타데이터 전부
- **로그 원문 그대로는 보내지 않습니다** — 마스킹 + 줄 수·길이 제한을 거친 것만, 그리고
  최근 15분 창의 로그만 보냅니다

## 4. 학습·보존 정책

- **No-training (확정)** — Anthropic Commercial Terms(2025-06-17 발효) Section B
  "Customer Content": **"Anthropic may not train models on Customer Content from Services."**
  API 입출력을 모델 학습에 쓰지 않음이 계약 조항으로 명시돼 있습니다.
  <https://www.anthropic.com/legal/commercial-terms>
- **보존(retention)은 미확정입니다.** 조직 설정·모델별 요건이 다릅니다. 도입 시점에 조직
  콘솔의 retention 설정과 최신 정책 문서로 확인하고 이 절을 갱신합니다.
  확인 전에는 **"학습 불가는 계약으로 확정, 보존 기간은 확인 절차 포함"** 으로 서술합니다.

## 5. 폴백·열화 시

- **Ollama 폴백(온프렘)** — 외부 전송 0건. 같은 마스킹 파이프라인을 통과하되 목적지가
  사내이므로, 외부 전송 규정이 강화되면 **즉시 전환 경로**가 됩니다.
- **열화 모드(LLM 전멸)** — 외부 전송 0건. 코드 선판정 문장만으로 회신합니다.

## 6. 검증 방법

```bash
cd bot
python -m gateway.selftest   # 원문 호스트명·IP·고객그룹·비허용 필드가 전송 전문에 없음을 자동 검증
python -m gateway.llm        # 드라이런 — 외부 호출 없이 "전송 전문 전체 + 내부 가명 맵"을 출력
```

두 번째 명령이 **이 명세표의 시연**입니다. 문서를 믿으라고 하지 않고 실제로 나가는 전문을
그대로 보여줍니다.
