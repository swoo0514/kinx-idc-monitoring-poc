# LLM 전송 데이터 계약 — 외부 LLM 데이터 반출 및 통제 명세

본 문서는 외부 LLM(Large Language Model) 서비스로 전송되는 데이터 항목 및 보안 통제 정책을 정의하는 Single Source of Truth (Owner) 명세서입니다. 본 문서의 정의를 바탕으로 구현 코드(`bot/gateway/masking.py`, `bot/gateway/collector.py`)가 동작하며, 셀프테스트 검증을 통해 문서와 코드 간의 정합성을 유지합니다.

---

## 1. 데이터 통제 3대 원칙

1. **단일 반출 경로 (Single Egress Gateway):** 외부 LLM 통신은 게이트웨이 모듈 한 곳에서만 전담하여 수행합니다. 수집 에이전트, Zabbix, Wazuh 등 개별 관측 시스템의 외부 직접 통신을 원천 차단합니다.
2. **화이트리스트 기반 직렬화 (Whitelist-based Serialization):** 명시적으로 허용된 필드만 직렬화하여 전송합니다 (`build_llm_context` 함수 기반). 허용 목록에 포함되지 않은 데이터는 코드 구조상 전송이 불가능하여 유출 가능성을 근본적으로 차단합니다.
3. **양방향 가명화 (Bi-directional Anonymization):** 주요 식별자(호스트명, IP, 그룹명)는 `[host-1]` 형태의 가명 토큰으로 치환하여 외부 전송합니다. 회신 데이터 수신 시 게이트웨이가 토큰을 역치환하여 Slack에 실명으로 출력합니다. (가명 매핑 정보는 게이트웨이 프로세스 메모리에만 국한되어 존재합니다. 단 **역치환이 끝난 분석 결론 원문은 판정 이력 저장소에 실명으로 보관**됩니다 — 아래 4절.)

---

## 2. 전송 허용 데이터 명세 (화이트리스트)

| 전송 항목 | 데이터 예시 | 데이터 처리 및 통제 방식 |
|---|---|---|
| **알림명** | `Filesystem /data 사용률 92% on [host-1]` | 호스트명 부분 가명화 처리 |
| **통합 심각도** | `SEV2` | 원본 유지 (통합 표준 눈금) |
| **발생 시각** | Unix Timestamp | 원본 유지 |
| **호스트 식별자** | `[host-1]` | **가명화 처리** |
| **호스트 그룹** | `[group-1]` | **가명화 처리** (MSP 고객사 식별 정보 보호) |
| **트리거 설명 및 조건식** | `last(/[host-1]/vfs.fs.size[...])>90` | 조건식 내부 호스트 식별자 가명화 처리 |
| **메트릭 키·단위·추이** | `vfs.fs.size[/data,pused]`, `%`, 수치 배열 | 원본 유지 (비식별 지표 수치 데이터) |
| **로그 라인 (Loki)** | `... [host-1] backup: mysqldump from [ip-2]` | 라인 내 호스트명·IP 가명화 + **라인당 300자 / 최대 40줄 제한** |
| **보안 경보 (Wazuh)** | `{level:10, desc:"brute force on [host-1]"}` | 설명 항목 내 식별자 가명화 + **최대 20건 제한** |
| **보안 경보 규칙 식별자** | `{rule_id:"550", groups:"syscheck,pci_dss_11.5"}` | 원본 유지 — 비식별 공통 사양 (규칙 번호 및 그룹명). 봇이 보안 이벤트 유형을 인지하여 노이즈성 변경과 유의미한 변경을 구별하기 위한 필수 정보 |
| **파일 변경 경로 (FIM)** | `syscheck.path` ➔ `/etc/ssh/sshd_config`<br/>`syscheck.event` ➔ `modified` | **경로 문자열 가명화 필터 적용** — 경로 내 호스트명·IP 포함에 따른 유출 방지 |
| **선판정 결과** | `신규 — 최근 90일 내 발생 이력 없음...` | 원본 유지 (코드 기반 자동 생성 문장) |
| **교차 소스 조회 상태** | `{"logs":"ok","security":"unavailable"}` | 원본 유지 — 지정 상태 문자열 3종(`ok`/`unavailable`/`disabled`)만 허용하며, 기타 미정의 값은 `unknown`으로 강등 처리 |
| **과거 분석 결론 (구조화)** | `{match:"동일 사건", verdict:"만성", days_ago:12, 확인:"미확인(봇 출력)"}` | 원본 유지 — 자유 서술이 없는 구조화 필드이며 식별자를 포함하지 않음. 매칭 강도와 사람 검증 여부를 함께 전송하여 모델이 과거 판정의 신뢰도를 구분하도록 강제 |
| **과거 분석 결론 (본문)** | `2일 전 결론: [host-1] 상류 지연` | **조건부 전송** — `GATEWAY_PRIOR_MODE=full` + 사람이 정답으로 확인한 결론 + 전역 이름 표 보유 + 가명화 후 잔여 식별자 검사 통과 시에만 전송. 하나라도 미충족 시 본문을 제외하고 구조화 필드만 전송(Fail-closed). 최대 2건 · 건당 600자 |

> **교차 소스 조회 상태 통제 목적:** "시스템 장애로 인한 조회 실패"와 "실제 보안 신호 없음" 상태를 구별하지 않을 경우, Wazuh Indexer 장애 시 봇이 "침해 흔적 없음"으로 잘못 단정하는 오류가 발생하므로 해당 조회의 상태 구별을 계약 수준에서 강제합니다.

## 3. 전송 차단 데이터 명세 (명시적 차단 항목)

- **모든 종류의 자격 증명 (Credential):** Zabbix 토큰, 게이트웨이 인증 토큰, SNMP Community, 계정 비밀번호 등
- **식별자 원문 데이터:** 호스트명, 공인/사설 IP 주소, 고객사명 원문 (가명 토큰으로 전면 치환)
- **개인식별정보 (PII):** 사용자 계정명, 이메일 주소, Slack 채널명 등
- **화이트리스트 외 메타데이터:** Zabbix 이벤트/트리거 메타데이터 중 허용 목록에 포함되지 않은 전체 항목
- **로그 원문 데이터:** 마스킹 필터링, 글자 수/줄 수 제어, 최근 15분 시간 창(Window) 제어를 통과하지 않은 원문 로그 전송 차단

## 4. 데이터 학습 및 보존 정책

- **모델 학습 제외 (No-training Policy, 확정):**  
  Anthropic Commercial Terms (2025-06-17 발효) Section B "Customer Content" 조항 준수:  
  *"Anthropic may not train models on Customer Content from Services."*  
  API 입출력 데이터는 모델 학습 목적으로 활용되지 않음이 상용 계약 조항으로 명시되어 있습니다 ([Anthropic Commercial Terms](https://www.anthropic.com/legal/commercial-terms) 참조).
- **로컬 보관 (판정 이력 저장소):**  
  역치환이 끝난 **분석 결론 원문은 게이트웨이 로컬 SQLite 에 실명으로 보관**됩니다(`GATEWAY_STORE_FILE`). 전송 대상이 아니라 사후 측정과 과거 결론 연계(`bot/GATEWAY_GUIDE.md` §25-6)의 재료입니다. 통제는 다음과 같습니다 — 파일 권한 `0600`(디렉토리 `0700`), 서술 보관 30일(행 자체는 90일)로 **서술을 먼저 삭제**, 프롬프트 원문은 미보관(결론만 보관). 이 원문을 다시 외부로 보낼 때는 마스킹을 재수행하며, 가명화 후 잔여 식별자가 검출되면 본문을 전송에서 제외합니다.
- **데이터 보존 기간 (Data Retention, 검토 중):**  
  조직 설정 및 적용 모델별 요구사항이 상이합니다. 프로덕션 도입 시점에 관제 조직 콘솔의 보존 설정 및 최신 정책 문서를 검증하여 확정합니다. (*현재 시점 기준: "학습 불가 규정은 계약으로 확정, 보존 기간은 확정 절차 진행 중"으로 정의함*)

## 5. 장애 및 폴백(Fallback) 상황 대응 정책

- **Ollama 폴백 (온프레미스 내장 모드):**  
  외부 데이터 전송 건수 0건. 동일한 마스킹 파이프라인을 거쳐 사내 내부망으로 전달되므로, 보안 정책 강화 시 **즉시 전환 가능한 대안 경로**로 활용합니다.
- **열화(Degraded) 모드 (LLM 불통 상황):**  
  외부 데이터 전송 건수 0건. 코드 기반 선판정 문장만 수집하여 회신합니다.

## 6. 데이터 반출 검증 방법

```bash
cd bot
# 전송 전문 내 원문 호스트명·IP·고객그룹 및 미허용 필드 포함 여부 자동 검증
python -m gateway.selftest

# 드라이런(Dry-run) 실행 — 외부 API 호출 없이 전송 전문 및 가명 매핑 테이블 출력
python -m gateway.llm
```

`gateway.llm` 실행을 통해 실제 외부로 반출되는 데이터 전문 및 내부 가명화 매핑 상태를 시각적으로 검증할 수 있습니다.

*관련 가이드:* 외부 도구(HolmesGPT 등) 연동 시 마스킹을 적용하는 이그레스 프록시 설정은 [`masking/MASKING_GUIDE.md`](../../masking/MASKING_GUIDE.md) 가이드를 참조합니다.
