# ADR-003 — AIOps: 왜 사지 않고 얇게 만들었나

**판정: PoC 단계에서는 자체 제작이 맞다. 다만 우리 봇은 유지할 제품이 아니라 검증 도구다.**

"이런 AI 로그분석 서비스가 이미 있는데 왜 만들었냐"에 대한 답이자, 프로덕션 도입 시
build vs buy 판단 자료입니다.

## 1. AIOps는 실재하고 성숙한 시장이다 — 몰라서 만든 게 아니다

세 갈래로 나뉘고, **우리 봇은 앞의 둘을 얇게 합친 것**입니다.

- **이벤트 상관·노이즈 감축** (우리 봇의 "병합") — 상용 Moogsoft / BigPanda / PagerDuty AIOps,
  OSS **Keep**. 10년 넘은 성숙 분야입니다.
- **LLM 기반 근본원인 분석** (우리 봇의 "초동 분석 회신") — 비교적 최신. 상용은 Grafana SIFT /
  Datadog Bits AI 등이 붙이는 중, OSS는 **HolmesGPT**, **k8sgpt**.
- **로그·메트릭 이상탐지** — OpenSearch ML Commons(Wazuh Indexer가 OpenSearch라 직접 연계 가능),
  Elastic ML(라이선스 주의), Prophet/PyOD 등.

## 2. OSS 후보의 스택 적합성

| 도구 | 담당 | 적합성 (Zabbix/Loki/Wazuh, IDC 물리·VM) |
|---|---|---|
| **Keep** | 알림 상관·관리·워크플로 | **높음** — 스택 무관, Zabbix 연동 있음 |
| **HolmesGPT** | LLM 원인 조사 | **높음** — VM/베어메탈 지원, Zabbix·Loki·OpenSearch·MySQL toolset 내장 |
| **k8sgpt** | LLM 진단 | **낮음** — 쿠버네티스 전용 |
| **OpenSearch anomaly detection** | 이상탐지 | 높음 — Wazuh Indexer가 OpenSearch. 단 LLM 트리아지는 아님 |

> **핵심 함정: OSS AIOps의 상당수가 쿠버네티스/클라우드네이티브를 전제합니다.**
> IDC의 물리·VM + Zabbix 스택에는 직접 안 맞는 것이 많습니다. 도구를 고를 때
> "좋은 도구인가"보다 **"우리 스택 모양에 맞는가"** 를 먼저 봐야 합니다.
>
> HolmesGPT에 대해서는 착수 당시의 "k8s 지향이라 안 맞을 것"이라는 우려가 **공식 문서
> 확인으로 폐기**됐습니다("any infrastructure: VMs, bare metal, cloud"). 우려를 사실로
> 확인하지 않고 배제했다면 잘못된 결론에 도달했을 것입니다.

## 3. 왜 사지 않았나

1. **데이터 주권·온프렘** — 상용 AIOps 대부분이 SaaS라 텔레메트리가 벤더 클라우드로 갑니다.
   온프렘 + MSP 고객 데이터라 통째 외부 전송은 부담입니다. 우리는 사내 보관 + **마스킹된
   조각만** LLM으로 보냅니다(그래서 전송 데이터 계약과 마스킹이 필요했습니다).
2. **비용** — 호스트/용량당 과금(Datadog·Dynatrace·Splunk·Moogsoft)은 사내+MSP 규모에 큽니다.
   우리는 기존 OSS 스택 + LLM API 종량제입니다.
3. **기존 스택 적합성** — 상용은 대개 자기 플랫폼으로 데이터를 이관하는 것을 전제합니다.
   우리 봇은 기존 스택 위에 API로 얹어 **재플랫폼이 없습니다.**
4. **PoC의 목적** — 개념과 가치를 싸게 검증하고 요구사항을 파악하는 것이지 완제품 제작이
   아닙니다.

## 4. 정직한 포지션

- 우리 봇 ≈ **Keep(상관) + HolmesGPT(LLM 원인분석)** 을 우리 스택과 MSP 심각도 설계에 맞춰
  얇게 만든 것입니다.
- 한 문장으로: *"AIOps 시장을 알고, 우리 제약(온프렘·MSP·비용)에 맞춰 싸게 검증했으며,
  프로덕션은 OSS를 요구사항에 기반해 도입 검토한다."* — 몰라서가 아니라
  **검증 → 요구사항 발굴 → 도입 판단** 순서입니다.
- **반대편도 인정합니다.** 장기 운영은 유지보수되는 전용 도구가 자체 봇보다 낫습니다.
  **우리 봇은 검증용이지 유지할 제품이 아닙니다.** 이것을 숨기지 않는 것이 신뢰도를 높입니다.

## 5. 그래서 무엇이 남았나

PoC가 만든 진짜 산출물은 봇 자체가 아니라 **요구사항**입니다 — 마스킹 거버넌스, 온프렘 LLM,
Zabbix 조회 깊이, 환각 통제, 30초 예산. 이 요구사항들이 그대로 **OSS 평가의 채점 기준**이
됐습니다.

그 기준으로 실측한 결과가 [ADR-001(Keep 채택)](adr-001-keep-adopt.md)과
[ADR-002(HolmesGPT 하이브리드)](adr-002-holmesgpt.md)입니다.
