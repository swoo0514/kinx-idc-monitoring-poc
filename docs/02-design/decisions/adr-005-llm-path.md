# ADR-005 — LLM 파이프라인: Claude 주 경로 + Ollama 폴백 + 열화 모드

**판정: Claude 모델을 메인 분석 경로로 채택**  
실측 검증을 통해 30초 이내 처리 지연 시간(Latency) 예산 충족을 확인하였으며, 서비스 장애 시 Ollama ➔ 열화(Degraded) 모드로 전환되는 3단계 폴백(Fallback) 아키텍처를 적용합니다.

---

## 1. 검증 배경 및 목적

데모 C 시나리오의 핵심 요구사항은 "단순 알림 수집이 아닌 **인시던트(사건) 확정 후 30초 이내 분석 결과 회신**"입니다. LLM API 호출 시간이 해당 예산을 초과할 경우 전체 시나리오 생성이 불가하므로, 파이프라인 구현에 앞서 성능 측정을 수행했습니다.

---

## 2. 성능 측정 조건

- **대상 모델:** `claude-opus-4-8` (Extended Thinking 비활성화, `max_tokens=2048`, 3회 반복 측정)
- **테스트 프롬프트:** 데모 C 실전 페이로드 모사 (알림 + 코드 기반 선판정 + 메트릭 + Loki 로그 + Wazuh 컨텍스트 / *실환경 데이터 제외, 랩 시뮬레이션 데이터 약 1.5KB 적용*)
- **출력 제약 조건:** Slack 단일 메시지 규격 준수 (1,500자 이내 제한)
- **측정 유틸리티 및 가이드:** [`bot/tools/latency_bench.py`](../../../bot/tools/latency_bench.py), 실행 절차는 [`bot/BENCH_GUIDE.md`](../../../bot/BENCH_GUIDE.md) 참조

---

## 3. 측정 결과

| 실행 회차 (Run) | TTFT (First Token) | 총 소요 시간 | 출력 토큰 수 | 출력 글자 수 | 종료 상태 |
|---|---|---|---|---|---|
| 1 | 1.27s | 14.84s | 863 | 1,096자 | `end_turn` |
| 2 | 1.00s | 13.72s | 793 | 970자 | `end_turn` |
| 3 | 0.96s | 14.11s | 791 | 1,004자 | `end_turn` |

- **응답 속도:** 총 소요 시간 중앙값 **14.1초** (최대 14.8초), TTFT(First Token) 중앙값 1.0초, 약 60 tokens/sec
- **종료 정상성:** 3회 측정 모두 정상 종료(`end_turn`) 확인 (문맥 잘림 현상 없음)
- **출력 글자 수:** 프롬프트 제약 조건 지시만으로 평균 약 1,000자 내외로 생성되어 Slack 제한(1,500자) 수용 범위 충족
- **안정성:** 소요 시간 편차 1.1초 수준으로 안정적 응답 특성 확인

---

## 4. 평가 판정

**성능 요건 통과 (최대 소요 시간 14.8초 ≤ 30초 예산)**

30초 예산 분해: LLM 처리 최대 15초 + 컨텍스트 수집 및 Slack 전송 처리 ≈ 총 20초 이내 수용 가능.  
*(참고: 게이트웨이 파이프라인 완성 후 실측 데이터 기준 End-to-End 총 **15.77초** 소요 확인됨 — 컨텍스트 수집 0.16초 + LLM 연산 15.03초 + Slack 전송 0.58초)*

---

## 5. 측정 결과 기반 아키텍처 설계 결정

- **API 재시도(Retry) 미적용:** LLM 호출 실패 시 재시도를 수행할 경우 30초 처리 예산을 초과하게 됩니다. 이에 따라 `max_retries=0`으로 설정하고, 타임아웃 발생 시 재시도 대신 **즉시 폴백(Fallback) 단계로 전환**합니다.

```text
Claude  ➔  (타임아웃/오류)  ➔  Ollama  ➔  (오류)  ➔  열화(Degraded) 모드
                                                    (코드 선판정 및 병합 결과만 반환)
```

- **열화(Degraded) 모드 구성 사유:** LLM 서비스 전체 장애 발생 시에도 시스템 응답성을 유지하기 위한 **안전 장치(Safety Net)**입니다. LLM 응답이 불가한 상황에서도 봇이 응답을 중단하지 않고, 코드 기반 판정 결과(만성/신규 구분, 병합된 알림 수 등)를 즉시 회신합니다. (*실제 API 크레딧 소진 테스트 시 정의된 열화 모드로 정상 동작함을 검증했습니다.*)
- **HTTP 상태 코드별 분기 처리:** 일시적 오류(429 Rate Limit, 529 Overloaded) 발생 시에는 폴백 파이프라인으로 전환하며, 인증/요청 오류(400 Bad Request, 401 Unauthorized) 발생 시에는 즉시 실패 처리합니다.

---

## 6. 향후 과제 및 검토 항목

- [ ] **Ollama 폴백 실측:** 랩 VM 환경 내 `--provider ollama` 옵션 적용을 통한 Cold/Warm Start 지연 시간 측정 (예산 초과 시 "온프렘 인프라 스펙 상향 필요성"을 로드맵에 명시)
- [ ] **모델 선정 최적화:** Opus vs Sonnet 간 처리 지연 시간, 비용, 분석 품질 비교 검토 (`--claude-model` / `LLM_CLAUDE_MODEL` 설정을 통한 동적 전환 지원)
- [ ] **Extended Thinking 옵션 영향도 평가:** Thinking 활성화 시 분석 품질 향상 대비 지연 시간 트레이드오프 측정
