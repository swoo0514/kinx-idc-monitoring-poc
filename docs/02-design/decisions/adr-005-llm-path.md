# ADR-005 — LLM 경로: Claude 주 경로 + Ollama 폴백 + 열화 모드

**판정: Claude를 주 경로로 쓴다.** 30초 예산 안에 들어오는 것을 실측으로 확인했고, 실패 시
Ollama, 그것도 실패하면 열화 모드로 3단 폴백한다.

## 왜 재야 했나

데모 C의 약속이 "알림이 아니라 **사건**이 확정된 뒤 30초 안에 분석 회신"입니다. LLM 호출이
그 예산 안에 안 들어오면 시나리오 자체가 성립하지 않으므로, 구현 전에 먼저 쟀습니다.

## 측정 조건

- 모델 `claude-opus-4-8`, thinking 끔, `max_tokens=2048`, 3회 반복
- 프롬프트 = 데모 C 실전 페이로드 모사(알림 + 코드 선판정 + 메트릭 + Loki 로그 + Wazuh 컨텍스트).
  **전부 가짜 랩 데이터 약 1.5KB** — 실환경 데이터를 쓰지 않았습니다.
- 출력 제한 "Slack 1메시지(1500자 이내)"
- 측정 도구 [`bot/latency_bench.py`](../../../bot/latency_bench.py), 방법은
  [`bot/BENCH_GUIDE.md`](../../../bot/BENCH_GUIDE.md)

## 결과

| run | TTFT | 총 시간 | 출력 토큰 | 출력 자수 | 종료 |
|---|---|---|---|---|---|
| 1 | 1.27s | 14.84s | 863 | 1,096 | end_turn |
| 2 | 1.00s | 13.72s | 793 | 970 | end_turn |
| 3 | 0.96s | 14.11s | 791 | 1,004 | end_turn |

- 총 시간 중앙값 **14.1초** / 최대 **14.8초**, TTFT 중앙값 1.0초, 약 60 tok/s
- 3회 전부 자연 종료(`end_turn`) — 잘림 없음
- 출력이 약 1,000자로 **프롬프트 지시만으로** Slack 제한(1,500자) 안에 수렴
- 편차 1.1초로 안정

## 판정

**통과.** 최대값 기준 14.8초 ≤ 30초.

30초 예산 분해: LLM 최대 15초 + 컨텍스트 수집 + Slack 게시 ≈ 20초 안쪽.
(게이트웨이 완성 후 실 데이터 end-to-end **15.77초**로 확인됨 — 수집 0.16 + LLM 15.03 +
Slack 0.58.)

## 이 측정이 만든 설계 결정

**재시도를 하지 않습니다.** 1회 재시도가 발생하면 그 순간 30초를 넘깁니다. 그래서
`max_retries=0`으로 두고, 타임아웃 시 재시도 대신 **폴백**으로 넘깁니다.

```
Claude  →  (타임아웃/실패)  →  Ollama  →  (실패)  →  열화 모드
                                                    선판정·병합 결과만 회신
```

열화 모드가 있는 이유는 **데모 안전망**입니다. LLM이 전멸해도 봇은 침묵하지 않고 코드가
판정한 것(만성/신규, 병합된 알림 수)만이라도 회신합니다. 실제로 크레딧이 소진된 상태에서
설계대로 동작하는 것을 확인했습니다.

상태코드별 분기: 429/529는 일시적이라 폴백, 400/401은 즉시 실패로 처리합니다.
