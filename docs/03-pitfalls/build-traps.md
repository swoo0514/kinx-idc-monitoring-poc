# 구축 함정 색인 — 현상별 트러블슈팅 가이드

실험 환경(랩) 구축 과정에서 발생한 주요 장애 및 트러블슈팅 사례를 **발생 현상(Symptom) 중심**으로 정리한 색인 문서입니다. 문제 발생 시 현상을 바탕으로 원인 및 관련 가이드 문서의 해결 절차를 신속히 참조할 수 있도록 구성되었습니다.

---

## 1. 패키지 설치 및 저장소 연동 (Installation & Repository)

| 발생 현상 (Symptom) | 추정 원인 (Root Cause) | 참조 가이드 및 조치 방향 |
|---|---|---|
| **Docker 저장소 404 에러 발생** | Rocky Linux 9 환경에서 `$releasever`가 `9.0`으로 확장되나 Docker 레포지토리는 Major(9) 버전만 제공함 | [`01-build/01-observability-core.md §1-1`](../01-build/01-observability-core.md) — 레포지토리 파일 내 `$releasever`를 9로 고정 |
| **Python 패키지 설치 실패** | 배포판 고정 저장소 패키지 버전 미달 (OpenSSL·Expat 등 상위 라이브러리 요구) | `requirements.txt` 버전 핀 고정 완화 또는 컨테이너 환경 활용 (운영 환경 도입 시 사전에 검증해야 할 리스크 항목) |
| **MariaDB 의존성 라이브러리 버전 부족** | 마이너 버전 고정 레포지토리에 패키지 미포함 | [`lab/mariadb/REPL_VM_GUIDE.md`](../../lab/mariadb/REPL_VM_GUIDE.md) — 상위 패키지 레포지토리 지정 수집 |

> **[운영 교훈]** 마이너 버전이 고정된 OS 배포판 상에서 최신 애플리케이션 스택을 구성할 경우 **저장소 버전 갭(Repository Gap)**이 필연적으로 발생합니다. 이는 실환경 도입 시 사전 점검해야 할 주요 기술 리스크에 해당합니다.

## 2. 분산 클러스터 구축 (Wazuh 6개 노드)

| 발생 현상 (Symptom) | 추정 원인 (Root Cause) | 비고 및 조치 지침 |
|---|---|---|
| **TLS 인증서 검증 실패 (Handshake Refused)** | **VM 간 노드 시간 동기화(NTP) 오차 발생** | **분산 배포 1순위 장애 원인.** 시간 동기화 절차를 인프라 구성의 최선순위로 배치 |
| **Wazuh Manager 설치 후 인덱싱 데이터 미전송** | **Filebeat 데몬 추가 설치 누락 및 설정 빈 상태** | Filebeat 추가 설치 및 TLS/SSL 관련 설정 직접 구성 필요 |
| **Dashboard 상에서 Manager 상태가 Offline으로 표기** | **대시보드 관련 설정 파일 이원화** | `opensearch_dashboards.yml` (Indexer) 및 `wazuh.yml` (Manager) 설정 분리 점검 |
| **노드별 설정 파일 구성 불일치** | 패키지가 생성한 `opensearch.yml` 의 주석 처리 형태가 노드별로 상이 (`discovery.seed_hosts` · `cluster.initial_master_nodes` 가 주석 상태로 남는 경우 발생) | 3개 노드 전체를 육안 점검. 노드 개별 설정값과 클러스터 공통 설정값 분리 확인 |
| **단계별 진행 중 네트워크 통신 블로킹** | 각 구축 단계별 필수 방화벽 포트 개방 누락 | 초기 인프라 구성 시 필요 포트 일괄 개방 처리 |
| **단일 Indexer 노드 다운 시 Cluster 상태가 Red로 전환** | Indexer 레플리카(Replica) 설정값이 0으로 지정됨 | 단일 노드 다운 시에도 Green 상태를 유지하려면 레플리카 설정을 1 이상으로 상향 필요 |

## 3. 관측 에이전트 배포 (Agent Deployment)

| 발생 현상 (Symptom) | 추정 원인 (Root Cause) | 비고 및 조치 지침 |
|---|---|---|
| **신규 zabbix-agent2 데몬 기동 실패** | **기존 구버전 zabbix-agent가 동일 포트(10050) 선점** | Ansible 배포 플레이북 내 기존 에이전트 데몬 정리 및 멱등성 확보 로직 추가 |
| **로그 수집기(Alloy)의 로그 파일 읽기 권한 오류** | 로그 파일 권한이 `root:root 0600`으로 설정되어 서비스 계정 접근 불가 | 수집 대상을 저널(Journald) 소스로 전환하거나 계정 그룹 권한 부여 |
| **DB 모니터링 플러그인 접속 실패** | `@'%'` 계정 권한 설정은 `localhost` 접속을 커버하지 않음 | DB 내 `localhost` / `127.0.0.1` 전용 접속 계정 별도 생성 |
| **설정 파일 반영 후 서비스 기동 실패** | 설정 파일의 소유자/그룹 권한이 서비스 계정과 불일치 | 파일 권한 및 서비스 실행 계정 사전 점검 |

## 4. 시각화 및 대시보드 표출 이슈 (Visualization & UI Display)

*설정은 정상이나 대시보드 화면상에 데이터가 정상 표출되지 않는 장애 패턴입니다.*

| 발생 현상 (Symptom) | 추정 원인 (Root Cause) | 비고 및 조치 지침 |
|---|---|---|
| **시계열 메트릭 패널 데이터 갱신 정지** | Grafana Zabbix 데이터소스의 **조회 캐시 기본값(`cacheTTL`)이 1시간**으로 설정됨 | 캐시 유지시간을 1분으로 단축 재설정 |
| **호스트 표시명 변경 후 변수 필터 동작 불가** | 상기 데이터소스 캐시 지연 현상과 동일 원인 | 호스트 온보딩이 빈번한 랩 환경에서는 캐시 시간을 단축 처리 |
| **대시보드 전체 패널에 "No data" 표기** | 자동 등록된 호스트가 `Discovered hosts` 그룹에 할당되나 **조회 계정에 권한 누락** | Zabbix ➔ User groups ➔ Host permissions 권한 설정 점검 |
| **월간 대시보드 패널 데이터 표출 불가** | 30일 조회 창 설정 시 Trends 데이터를 참조하나 해당 아이템의 Trends 미설정 | 리포트 패널 설정 시 `useTrends=false` 옵션 적용 |
| **필터링 규칙 설정이 적용되지 않음** | Grafana Zabbix 플러그인 백엔드가 Go Regexp 사양을 사용하여 **부정 Lookahead `(?!...)` 구문을 무시함** | 에러 없이 필터만 미적용되므로 대체 정규식 표현 적용 |
| **아이템 필터링 결과가 출력되지 않음** | 정규식 슬래시(`/`) 미포함 시 **완전 일치(Exact Match)**로 처리됨 | 정규식 적용 시 `/pattern/` 형태로 슬래시 감싸기 적용 |
| **호스트 필터링 미동작** | Zabbix 호스트 필터는 기술명(Technical Name)이 아닌 **표시명(Visible Name)** 매칭 기준 동작 | 호스트 표시명 기준 필터 조건 작성 |
| **타 고객사 데이터가 대시보드 패널에 혼입** | 템플릿 변수의 `allValue: ".+"` 설정 사용 시 "전체" 조건이 타 테넌트 데이터까지 조회에 포함시킴 | 대시보드 멀티테넌시 권한 격리 및 변수 설정 점검 |
| **Grafana 서비스 기동 실패** | Correlation 프로비저닝 형식이 올바르지 않아 **전체 데이터소스 프로비저닝 중단** | [`01-build/01-observability-core.md §9-1`](../01-build/01-observability-core.md) — Root `type` 생략 및 `config.type: query` 명시 |

## 5. 연동 및 제어 파이프라인 (Integration & Wiring)

| 발생 현상 (Symptom) | 추정 원인 (Root Cause) | 비고 및 조치 지침 |
|---|---|---|
| **게이트웨이 웹훅 요청이 HTTP 422로 거부됨** | Zabbix 미디어 타입 매크로 오타로 인해 Null 값 전달 | 게이트웨이 파이프라인 내 Null 인자 수용 처리 강화 |
| **트리거 심각도 변경 사항 미반영** | 템플릿 프로토타입 수정 사항이 **이미 발견된 기존 트리거에 자동 반영되지 않음** | 템플릿 Unlink & Clear 실행 후 재연결 |
| **DB 복제 지연 트리거 미발화** | 트리거 조건이 `min(lag, 5m) > 임계치`로 설정되어 **지연 상태가 5분 이상 지속되어야 발화** | 장애 시뮬레이션 부하 주입 시간을 420초 이상으로 유지 |
| **`.env` 파일 수정 사항 미반영** | 프로세스가 기존 환경변수 값을 메모리에 유지함 | 환경변수 재적용(`source .env`) 및 프로세스 재기동 |
| **동일 알림에 대해 봇 카드가 중복 발송됨** | uvicorn `--workers` 옵션 적용 시 워커 프로세스별로 인메모리 버퍼가 따로 생성됨 | 게이트웨이를 단일 워커 프로세스로 기동 |
| **Keep UI 상에 워크플로 목록 미노출** | Keep 워크플로 정의 파일은 **Keep 서비스 재시작 시점에만 재로드** | `git pull` 후 Keep 백엔드 컨테이너 재시작 |
| **Keep UI에서 신규 워크플로 생성 시 500 에러** | Keep UI 모듈 내 워크플로 생성 기능 버그 | YAML 파일 직접 편집 또는 API 호출 방식으로 생성 우회 |
| **커스텀 분석 Toolset 누락** | 캐시 로드 과정에서 커스텀 Toolset이 비정상 누락됨 | CLI 실행 시 `--refresh-toolsets` 옵션 부여 |
| **대시보드 이미지 렌더링 정지** | 서버가 자기 공인 IP로 셀프 호출을 시도하나 Hairpin NAT 미지원으로 차단됨 | 렌더링 호출 주소(내부 주소)와 접속 링크 주소(공인 IP) 분리 설정 |
| **PDF 출력물 내 내비게이션 UI 포함** | `kiosk` 파라미터를 URL 인코딩하여 전송 시 정규 파라미터 미인식 | URL 파라미터 직접 전달 방식 적용 |
| **데이터 수집 완료 후 출력 단계에서 예외 발생** | 한국어 Windows 콘솔 환경(CP949)에서 대시(`—`) 등 특수문자 출력 시 `UnicodeEncodeError` 발생 | Standard Output 스트림을 UTF-8 인코딩으로 강제 고정 |

## 6. 호스트 식별자 및 명칭 불일치 (Host Identity)

| 발생 현상 (Symptom) | 추정 원인 (Root Cause) | 비고 및 조치 지침 |
|---|---|---|
| **Loki 로그 조회 건수 0건** | Zabbix 호스트명과 Loki `host` 라벨 값이 불일치 | 게이트웨이 `HOST_LABEL_MAP`을 통한 식별자 매핑 적용 (FQDN 정규화) |
| **보안 패널 드릴다운 연결 실패** | Wazuh `agent.name`과 Loki `host` 라벨 값이 불일치 | 3종 에이전트 배포 시 FQDN 명칭으로 일원화 |
| **`Could not resolve hostname` 에러** | SSH 별칭(Alias) 설정이 **작업자 PC 환경에만 존재함** | [`../01-build/hosts.md`](../01-build/hosts.md) 참조 — VM 내부 통신 시 사설 IP 사용 |
| **변수 드롭다운 목록에 변경 전 기존 호스트명 잔재** | 라벨 변경 이전에 수집된 시계열 스트림 데이터가 존재함 | Loki 데이터 보존 기간(Retention) 경과 후 자동 소멸 |

## 7. 스토리지 및 디스크 용량 관리 (Storage & Disk Management)

| 발생 현상 (Symptom) | 추정 원인 (Root Cause) | 비고 및 조치 지침 |
|---|---|---|
| **랩 VM 루트 디스크 용량 100% 포화** | MariaDB 바이너리 로그(binlog) 만료 정책 미설정으로 로그 무한 누적 | `expire_logs_days` 또는 `binlog_expire_logs_seconds` 설정 추가 |
| **Wazuh Indexer 인덱싱 작업 중단** | 인덱서 데이터가 루트 디스크를 점유하여 워터마크(Watermark) 도달 | 별도 스토리지 볼륨을 패키지 설치 전 마운트하여 마이그레이션 |

**MariaDB Binlog 포화 주의:** DB 복제 슬레이브의 SQL 스레드가 중단될 경우 마스터 노드는 미동기화된 Binlog를 삭제하지 못하고 보관합니다. 이로 인해 마스터 Binlog 및 슬레이브 Relay Log가 급격히 증가하여 디스크 포화를 유발할 수 있으므로, 대량 쓰기 테스트 진행 시 로그 만료 정책 설정이 필수적입니다.

## 8. 버전 관리 및 커밋 보완 (Commit Hygiene & Security)

| 발생 현상 (Symptom) | 추정 원인 (Root Cause) | 비고 및 조치 지침 |
|---|---|---|
