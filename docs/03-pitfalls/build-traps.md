# 구축 함정 — 증상으로 찾는 색인

랩을 세우면서 실제로 밟은 것들입니다. **증상을 먼저 적었습니다** — 막혔을 때 검색하는 것이
증상이기 때문입니다.

각 항목의 상세 절차는 원본 가이드에 있습니다. 여기서는 **어디를 보라고만** 가리킵니다.

---

## 설치·저장소

| 증상 | 원인 | 어디를 보나 |
|---|---|---|
| Docker repo가 404 | Rocky 9는 `$releasever`가 `9.0`으로 확장되는데 Docker repo는 major(9)만 제공 | [`01-build/01-observability-core.md §1-1`](../01-build/01-observability-core.md) — repo 파일의 `$releasever`를 9로 고정 |
| 파이썬 패키지가 설치 안 됨 | 고정 저장소가 최신 파이썬을 못 줌. OpenSSL·expat까지 상향을 요구 | requirements 핀을 완화하거나 컨테이너로. **이 갭 자체가 도입 리스크 실측** |
| MariaDB 의존 라이브러리 버전 부족 | 고정 마이너 저장소에 없어 최신 저장소에서 당겨와야 함 | [`lab/mariadb/REPL_VM_GUIDE.md`](../../lab/mariadb/REPL_VM_GUIDE.md) |

> **공통 교훈**: 마이너 버전이 고정된 배포판에서 최신 스택을 세우면 **저장소 갭**을 반드시
> 만납니다. 이것은 랩의 사고가 아니라 **실환경 도입에서 그대로 재현될 리스크**이므로
> 우회 방법과 함께 기록해 두는 것이 산출물입니다.

## 분산 설치 (Wazuh 6노드)

| 증상 | 원인 | 비고 |
|---|---|---|
| TLS 인증서가 거부됨 | **VM 간 시계가 어긋남** | **분산 배포의 1순위 함정.** 시간 동기화를 첫 단계에 둡니다 |
| 매니저를 설치했는데 로그가 인덱서로 안 감 | **Filebeat는 별도 설치**이고 설정 파일이 빈 상태 | SSL 설정을 수동으로 추가해야 합니다 |
| 대시보드에 Manager Offline | **설정 파일이 두 개**입니다 — 인덱서 연결과 매니저 연결이 서로 다른 파일 | 가장 헷갈리는 지점 |
| 노드마다 설정 파일 내용이 다름 | 인증서 도구가 생성한 설정의 주석 처리가 노드별로 다름 | 노드별 값과 공통 값을 분리해서 확인 |
| 포트가 막혀 단계마다 멈춤 | 방화벽 포트를 단계마다 하나씩 놓침 | 필요한 포트를 **미리 전부** 열어 둡니다 |
| 인덱서 1대를 껐더니 yellow가 아니라 **red** | 레플리카가 0 | "1대 다운 → green 유지"를 검증하려면 레플리카를 먼저 1로 |

## 에이전트 배포

| 증상 | 원인 | 비고 |
|---|---|---|
| 새 에이전트가 안 뜸 | **구버전 에이전트가 포트를 선점** | 배포 플레이북에 "기존 에이전트 정리"를 멱등으로 넣은 이유 |
| 로그 수집기가 파일을 못 읽음 | 로그가 `root:root 0600`이라 서비스 계정이 못 읽음 | 저널 소스로 전환하고 적절한 그룹에 넣습니다 |
| DB 모니터링 플러그인이 안 붙음 | `@'%'` 계정은 **localhost 접속을 커버하지 않음** | `localhost`/`127.0.0.1` 계정을 따로 만듭니다 |
| 설정 파일을 넣었는데 서비스가 안 뜸 | 설정 파일의 소유 그룹이 서비스 계정과 다름 | **기동 조건을 먼저 점검**합니다 |

## 표시 — "설정은 맞는데 화면만 틀린" 부류

**가장 시간을 많이 잡아먹는 부류입니다.** 원인을 코드에서 찾게 되는데 원인이 코드에 없습니다.

| 증상 | 원인 | 비고 |
|---|---|---|
| 메트릭 패널이 멈춰 보임 | Grafana Zabbix 데이터소스의 **조회 캐시 기본값이 1시간** | **같은 원인으로 두 번** 겪었습니다. 랩은 1분으로 낮춰 둡니다 |
| 호스트 표시명을 바꿨는데 변수 필터가 안 걸림 | 위와 같은 캐시 | 온보딩으로 호스트가 자주 바뀌는 환경에서는 캐시를 짧게 |
| **대시보드 전 패널 no data** | 자동 등록 호스트는 `Discovered hosts` 그룹에 들어가는데 **조회 계정에 그 그룹 권한이 없음** | Zabbix → User groups → Host permissions |
| 월 1회 값이 패널에 안 보임 | 30일 범위는 trends를 보는데 그 값이 trends에 없음 | 리포트 패널은 `useTrends=false` |
| 필터를 걸었는데 안 걸림 | Grafana Zabbix 플러그인 백엔드가 Go regexp라 **부정 lookahead `(?!...)`가 조용히 통과** | 필터가 안 걸리는데 에러도 없습니다 |
| 아이템 필터가 아무것도 안 잡음 | 슬래시로 감싸지 않으면 **완전 일치** | `/.../` 로 감싸야 정규식 |
| 호스트 필터가 안 걸림 | 호스트 필터는 **표시명**으로 매칭 (기술명 아님) | |
| **다른 고객 데이터가 패널에 섞임** | 템플릿 변수의 `allValue: ".+"` 가 "전체"를 "다른 고객까지"로 만듦 | 계정 권한과 별개로 **대시보드가 새면 안 됩니다** |
| Grafana가 아예 기동 실패 | correlation provisioning 형식 오류 → **데이터소스 프로비저닝 전체가 중단** | [`01-build/01-observability-core.md §9-1`](../01-build/01-observability-core.md) — root `type`은 생략하고 `config.type: query`는 명시 |

## 배선·연동

| 증상 | 원인 | 비고 |
|---|---|---|
| 웹훅이 422로 거부됨 | 미디어타입 매크로 오타로 값이 null | 게이트웨이가 null을 견디도록 보강했지만, **매크로 오타는 조용합니다** |
| 트리거 심각도를 바꿨는데 반영 안 됨 | 템플릿 프로토타입 변경이 **이미 발견된 트리거에는 자동 반영되지 않음** | 템플릿을 unlink-clear 후 재연결 |
| 복제 지연 트리거가 안 뜸 | 트리거가 `min(lag, 5m) > 임계`라 **5분을 버텨야** 발화 | 주입 시간을 420초 이상으로 |
| `.env`를 고쳤는데 안 먹음 | 프로세스가 옛 환경변수를 들고 있음 | **다시 source하고 재기동**합니다 |
| 봇 카드가 여러 개 뜸 | `--workers`를 붙여 워커마다 버퍼가 따로 생김 | 단일 프로세스로 |
| Keep UI에 워크플로가 안 보임 | 워크플로 파일은 **Keep을 재시작할 때만** 읽음 | `git pull` 후 백엔드 재시작 |
| Keep에서 새 워크플로 생성이 500 | Keep UI의 생성 버그 | 파일이나 API로 우회 |
| 커스텀 조사 toolset이 사라짐 | 캐시 로드 시 **조용히 누락** | `--refresh-toolsets` |
| 렌더가 멈춤 | 서버가 **자기 공인 IP로 자기에게 접속**하려다 막힘(헤어핀 NAT 없음) | 렌더는 내부 주소, 링크는 공인 주소로 분리 |
| PDF에 내비게이션이 찍힘 | `kiosk`는 값 없는 플래그라 인코딩해서 넣으면 안 먹음 | |
| 조회는 끝났는데 **출력에서** 죽음 | 한국어 Windows 콘솔이 기본 cp949 라 `—` 같은 문자에서 `UnicodeEncodeError` | 출력 스트림을 utf-8 로 고정. 조회가 성공한 뒤 터져서 원인이 눈에 안 띈다 |

## 이름 — 세 시스템이 같은 호스트를 다르게 부른다

| 증상 | 원인 | 비고 |
|---|---|---|
| 로그 조회가 0건 | Zabbix 호스트명과 Loki `host` 라벨이 다름 | 매핑을 걸면 0 → 정상. **이름 매칭이 병합의 전제조건** |
| 보안 패널 드릴다운이 안 먹음 | Wazuh `agent.name`과 Loki `host`가 다름 | 둘 다 FQDN으로 정규화 |
| `Could not resolve hostname` | SSH 별칭은 **작업자 PC에만** 있음 | [`../01-build/hosts.md`](../01-build/hosts.md) |
| 변수 드롭다운에 옛 이름이 남음 | 라벨을 바꾸기 전에 쌓인 스트림이 남아 있음 | 보존 기간이 지나면 사라짐. 과거 잔재일 뿐 |

## 저장 공간 — 조용히 차오르는 것

| 증상 | 원인 | 비고 |
|---|---|---|
| **랩 디스크가 100%** | binlog 만료 설정이 없어 무한히 쌓임 | 8일간 **아무도 몰랐다.** 아래 참조 |
| 인덱싱이 멈춤 | 인덱서 데이터가 루트 디스크를 채워 워터마크 도달 | 별도 볼륨을 마운트하고 **패키지 설치보다 먼저** 붙인다 |

**binlog가 특히 위험한 이유는 두 고장이 서로를 먹이기 때문입니다.** 슬레이브의 SQL 스레드가
멈춰 있으면 마스터는 아직 안 읽힌 binlog 를 **지울 수 없습니다.** 그래서 복제 중단이 곧
디스크 증가가 되고, 랩에서 마스터 binlog 15GB · 슬레이브 relay log 14GB 까지 갔습니다.

부하 주입 스크립트의 대량 쓰기가 binlog 를 1GB 단위로 만들기 때문에 **랩에서도 만료 설정이
필수**입니다. 실환경 도입에서도 같은 항목입니다.
