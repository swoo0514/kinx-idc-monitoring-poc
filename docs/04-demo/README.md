# 데모 — 무엇을 보여주는가

세 개의 데모가 하나의 흐름을 이룬다. **다 보인다 → AI가 사건으로 읽는다 → 승인 한 번으로
고친다.**

실행 명령은 전부 [`runbook.md`](runbook.md)에 있다. 이 문서는 "무엇을 보여주는 장면인가"만 적는다.

## 데모 A — 통합 관제

**보여주는 것.** 장애 하나를 주입했을 때 **메트릭·로그·보안 세 축이 같은 타임라인·같은
호스트에** 찍히는 것. 그리고 보안 이벤트 행을 클릭하면 그 호스트의 로그로 좁혀지는 드릴다운.

- 주입: `chaos/ssh_bruteforce.sh` (Wazuh 레벨 10 격상)
- 화면: Grafana `kinx-overview` 통합 대시보드
- 왜 이게 성과인가: 세 시스템이 각자 잘 돌고 있어도 **한 화면에서 같은 사건으로 보이지 않으면**
  사람이 세 개의 탭을 오가며 상관을 머리로 해야 한다. 이 드릴다운이 성립하려면 세 시스템이
  같은 호스트를 같은 이름으로 불러야 한다(FQDN 정규화).

## 데모 B — 자가 치유 (HITL 승인)

**보여주는 것.** 서비스가 죽고 → 봇이 조치 후보로 분류해 승인 큐에 올리고 → **사람이 버튼을
한 번 누르면** → Ansible이 재기동하고 **스스로 재검증**하는 것. 사람 개입은 Run 버튼 1회다.

- 주입: `chaos/service_down.sh`
- 화면: Keep 승인 큐 → 워크플로 실행 출력(`before: inactive -> after: active`)
- 왜 승인을 넣었나: MSP 계약이 "알림만"과 "직접 조치"로 갈리므로 **임의 조치가 불가능한 대상이
  실재한다.** `scope=notify_only` 태그가 조치 경로 자체를 차단하고, 워크플로 첫 줄이
  `playbook` 값을 확인하는 안전 게이트다. 진짜 안전판은 승인 버튼이 아니라
  **가역·멱등 플레이북 + 조치 후 재검증**이다.

## 데모 C — AI 초동 분석 (하이라이트)

**보여주는 것.** 서로 다른 트리거에서 따로 올라온 알림 N건을 봇이 **한 사건으로 병합**하고,
"복제가 고장 난 게 아니라 백업 부하가 I/O를 먹어서 밀린 것"이라고 **재프레이밍**하는 것.

- 주입: `chaos/repl_lag_contention.sh` (7분 필요)
- 화면: Slack 스레드의 병합 카드 + 인과 설명
- 설계·심사 반문 대비: [`scenario-c-replication.md`](scenario-c-replication.md)
- 왜 단일 도구로 안 되는가: Wazuh는 **자기가 수집한 데이터 안에서만** 상관한다. Zabbix 메트릭과
  Loki 로그는 애초에 그 룰 엔진에 들어가지 않는다. 세 시스템에 흩어진 조각을 하나의 사건으로
  묶는 일은 **어느 한 도구도 구조적으로 할 수 없다.**

### 변형 — 보안 축이 주연이 되는 케이스

브루트포스 **단독**은 흔한 잡음이다. 거기에 로그인 성공과 `/etc/ssh/sshd_config` 변경이
이어지면 성격이 달라진다. 봇이 셋을 한 사건으로 묶고 심층 조사가 2단계 공격으로 규명한다.
**축이 겹칠 때만 진짜 사건**이라는 설계가 화면으로 드러나는 장면이다 — 런북 §4-B.

## 주입 스크립트 ↔ 데모 대응

| 스크립트 | 무엇을 만드나 | 쓰이는 곳 |
|---|---|---|
| `ssh_bruteforce.sh` | Wazuh 레벨 10 보안 이벤트 | 데모 A 보안 축, 데모 C 변형 |
| `service_down.sh` | 서비스 정지 → 조치 후보 | **데모 B** |
| `repl_lag_contention.sh` | 복제 지연 + CPU/IO 압박 (자원 경합) | **데모 C 핵심** |
| `repl_lag.sh` | 복제 지연 (master 대량 쓰기) | 메트릭 깊이 — 상태는 정상인데 지연만 급등 |
| `error_burst.sh` | 로그 오류율 급등 | 메트릭 깊이 — 로그를 지표로 |
| `snmp_iface_error.sh` | 인터페이스 에러 반복 발화 | 알림 노이즈 Before |
| `seed_security.sh` | 보안 이벤트 시드 | 리포트·대시보드 표시용 |

스크립트별 실행 위치와 원리는 [`chaos/README.md`](../../chaos/README.md).

## 이 데모들이 못 보여주는 것

정직하게 적어 둔다 — [`../03-pitfalls/limits.md`](../03-pitfalls/limits.md).
요약하면 봇은 **판정을 코드로, 설명만 LLM으로** 한다. 병합 규칙과 만성/신규 판정은 사람이 정한
규칙이고, LLM이 스스로 찾아낸 것이 아니다. 그렇게 만든 이유(환각 통제)도 같은 문서에 있다.
