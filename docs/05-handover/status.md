# 프로젝트 현황 — 컴포넌트별 구현 상태 및 진행률 명세

> **[기준 정보]** 기준 커밋: `765800a` (2026-08-05 기준, 총 178개 커밋 반영)  
> 본 문서는 해당 시점의 사실을 기록한 현황 문서입니다. 이후 커밋 내역이 존재할 경우 본 표부터 재검증이 필요합니다.

구현 상태는 아래 정의된 3가지 범주로만 명시하며, 모호한 "완료" 표현은 쓰지 않습니다.

| 상태 구분 | 정의 및 검증 기준 |
|---|---|
| **랩 실증** | 실험 인프라(랩) 환경에서 End-to-End 전체 동작 및 수집/분석 결과를 직접 눈으로 확인함 |
| **코드 있음·미실증** | 소스 코드는 구현되었으나 End-to-End 통합 시뮬레이션 검증을 거치지 않음 |
| **미구현** | 설계 및 사양 검토만 수행된 상태로 소스 코드가 작성되지 않음 |

## 4. 식별된 구조적 결함 (Known Issues)

*(상세 내역: [`../03-pitfalls/structural-gaps.md`](../03-pitfalls/structural-gaps.md) 참조)*

- **선판정 과거 이력 카운트 포화 현상 (G3):** 조회 상한(200건)으로 인해 선판정 수치가 포화되어 만성 장애 랭킹 산출이 왜곡되는 현상이 존재합니다.
- **알림 병합 키 호스트명 정규화 미적용 (G4):** 호스트명 표기 방식이 다를 경우 동일 물리 노드의 알림이 독립 인시던트로 분리됩니다.
- **LLM API 호출 동시성 제어 한계 부재 (G7):** 단일 시점 대량 디바운스 마감 시 API 동시 호출 제한 로직이 없어 Rate Limit(429) 위험이 존재합니다. (실환경 적용 시 개선 필요)
- **게이트웨이 프로세스 재기동 시 인메모리 인시던트 유실 (G8):** 디바운스 대기 중인 열린 인시던트가 프로세스 재기동 시 소실됩니다. (자동 재기동 설정이 유실을 조용하게 만듦)
- **분류기 단어 매칭 범위 제약 (G2b):** 알림명 키워드 매칭 방식의 한계로, 미디어 타입 파라미터를 통한 `item_key` 직접 참조 방식으로의 전환이 요구됩니다.
