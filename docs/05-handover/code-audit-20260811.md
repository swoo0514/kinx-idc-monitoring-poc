## 2군 — 알림 유실 및 오판정  ✅ **전건 반영 완료 (2026-08-11)**

### 2-1. ★ 대기 알림 파일에 잠금 부재 `pending.py:64-70`

`drop()` 은 전체 파일을 읽어 재작성하며(`load()` → `_rewrite` → `os.replace`), 그 사이 다른
스레드의 `append()` 결과가 소멸합니다. 웹훅은 이미 200 을 반환한 뒤이므로 재전송되지 않습니다.
`drop` 은 이벤트 루프에서, `append` 는 워커 스레드에서 호출되며 잠금이 없습니다.

### 2-2. 멱등성 판정에 잠금 부재 `app.py:120-127`

웹훅 엔드포인트가 `async def` 가 아닌 동기 함수이므로 FastAPI 가 스레드풀에서 실행합니다.
`_seen` 딕셔너리에 잠금이 없어 (a) 순회 중 크기 변경 시 예외, (b) 확인·등록 사이의 경합으로
동일 이벤트 중복 통과가 발생합니다.

### 2-3. 수집 전면 실패가 "조회 정상" 으로 기록됨 `collector.py:187-192`, `incident.py:486`

Zabbix 수집을 `gather(return_exceptions=True)` 로 수행하므로 전건 실패해도 예외가 전파되지 않고
폴백 컨텍스트가 생성되지 않습니다. 게이트는 `logs`·`security` 두 축만 검사하므로, Zabbix 중단
구간의 사건이 전부 "교차 신호 없음(조회는 정상) — LLM 스킵" 으로 기록됩니다. `open_problems` 는
정상적으로 `unavailable` 이 되나 **게이트와 Slack 카드가 해당 축을 참조하지 않습니다.**

### 2-4. 명부 로드 실패 시 타 감시 서버 조회 `collector.py:50-63`

명부 로드 실패 시 환경 변수로 대체되며, 그 결과 MSP 알림의 이벤트·트리거 ID 를 사내 Zabbix 에
조회합니다. ID 부재 시 "90일 내 이력 없음 = 신규" 로 확정되고, ID 충돌 시 타 호스트의 트리거명·
지표·이력이 해당 고객 사건의 컨텍스트로 외부 전송됩니다. 어느 경우에도 예외가 발생하지 않습니다.

### 2-5. ★ 상한 초과 알림이 대기 파일에 영구 잔류 `incident.py:530-533` ↔ `app.py:57`

`max_alerts` 초과분은 인시던트에 포함되지 않으므로 `pending.drop([... for a in inc.alerts])`
대상에서 제외됩니다. 재기동마다 재투입되어 종료된 사건의 알림으로 신규 인시던트가 개설되며,
3회 초과 시 폐기됩니다. 원시 신호 카드도 게시되지 않습니다.

### 2-6. 재투입 시 원 사건 시각이 소실됨 `app.py:104-108`, `collector.py:177`

`Alert` 에는 단조 시계 기준 `recv` 만 존재하고 대기 레코드에 `clock` 필드가 없습니다.
`ZabbixEvent.clock` 은 수신 후 사용되지 않습니다. 재기동 후 재투입 시 로그·보안 조회 창을
**수집 시점 기준**으로 잡으므로, 1시간 전 사건은 실제 로그 구간을 조회하지 않습니다.
결과는 빈 목록에 `ok` 상태가 부여되어 "로그에 기록 없음" 으로 단언됩니다.

### 2-7. 절단 판정 기준이 1 어긋남 `collector.py:123`, `prejudge.py:66`

상한 200건으로 조회한 뒤 현재 이벤트를 제외하여 199건이 되나, 판정 기준은 `>= 200` 입니다.
`countOutput` 파싱 실패 시 21,585회 발생 항목이 `count_truncated: False` 로 기록됩니다.
셀프테스트는 200건을 직접 전달하므로 통과합니다.

### 2-8. 열린 문제 조회 상한이 "없음" 으로 승격됨 `collector.py:322-358`

`problem.get` 을 `limit: 100`, `eventid DESC` 로 조회한 뒤 5분 미만 항목을 제외합니다.
폭주 시 최근 100건이 전부 5분 미만이면 빈 목록에 `SOURCE_OK` 가 부여되어, 3시간째 미해소인
선행 문제가 "선행 문제 없음" 으로 단언됩니다.

### 2-9. Wazuh 조회가 부분 일치 `collector.py:434`

`{"wildcard": {"agent.name": "*{name}*"}}` 이므로 `db01` 조회 시 `customer-b-db01` 등의 경보가
포함됩니다. 해당 항목은 이번 사건 호스트만 등록된 마스커를 거치므로 **타 호스트 경로·설명이
원문으로 전송**되며, Slack 카드에는 이 호스트의 신호로 표시됩니다.

### 3-4. 배포 서버의 환경 변수가 검사 결과를 변경 `selftest.py:583-586` 외

### 3-5. 생존 신호가 부분 실패를 성공으로 판정 `heartbeat.py:82`

로그는 성공으로 남고 값은 적재되지 않으며, 아이템 부재로 `nodata()` 트리거도 동작하지 않습니다.

### 3-6. 미측정 자리표시자가 실측값으로 프롬프트에 포함됨 `incident.py:138-156`

- 3-6 측정 파일 미지정 시 연계 규칙을 비활성화. 예시값이 "실측값" 으로 프롬프트에 유입되던 경로
  차단.

### 2군 (2026-08-11) — 검사 선행 방식으로 반영

각 항목에 대해 **검사를 먼저 작성하여 실패를 확인한 후** 수정하였습니다. 사후 작성 시
반복 누락이 발생하였기 때문입니다(3군 자체 재점검 참조).

| 항목 | 검사가 잡은 내용 | 조치 |
|---|---|---|
| 2-1 대기 파일 | 120건 중 1건 소실 | 파일 접근 전체에 잠금 적용 |

### 3군 자체 재점검 (2026-08-11, 반영 직후)

반영분에 대해 동일 기준으로 재점검한 결과 5건의 미비를 확인하고 함께 반영하였습니다.

| 미비 | 내용 | 조치 |
|---|---|---|
| 우회 검사 범위 | `gateway/` 만 검사하여 상위 `bot/` 의 직접 호출을 미검출. `latency_bench.py` 가 해당 | 검사 범위를 `bot/` 까지 확대. 해당 파일은 사유와 함께 예외 목록에 등재(측정 도구이므로 출구 경유 시 측정값이 왜곡됨) |
| 절단 판정 | 수정만 하고 검사 미추가 | 3종 추가(조회 측 통보 True/False, 총계 수신 시 절단 아님) |
| 연계 규칙 비활성 | 동일 | 파일 미지정 시 규칙 0건·`measured` 공백을 검사로 고정 |
| 검사 수 대조 | 두 수치를 출력만 하고 판정하지 않음 | 반복문 실행을 감안한 허용 범위를 벗어나면 경고 출력 |
| 환경 변수 격리 | `_incident_checks` 는 미적용 상태였음 | `INCIDENT_CLASS_FILE`·`SITE_CLASS_KEYWORDS` 제거 후 실행하도록 변경 |

**남은 한계:** 우회 검사는 여전히 패턴 기반이므로 다른 공급자(예: `openai.`)나 신규 엔드포인트는
검출되지 않습니다. 검사 수 대조도 경고 출력이며 실패 처리는 아닙니다.
